## Challenge Tasks

### Task 1: GitHub-Hosted Runners
1. Create a workflow with 3 jobs, each on a different OS:
   - `ubuntu-latest`
   - `windows-latest`
   - `macos-latest`
2. In each job, print:
   - The OS name
   ```bash
    - name: The OS name 
      run: echo "The OS name is ${{ runner.os }}"
   ```
   - The runner's hostname
   ```bash
    - name: The runner's username 
      run: echo "The OS name is ${{ runner.name }}"
   ```
   - The current user running the job
   ```bash
    - name: The current user running the job 
      run: echo "The OS name is ${{ github.actor }}"
   ```
3. Watch all 3 run in parallel

Write in your notes: What is a GitHub-hosted runner? Who manages it?
```bash
It is a virtual environment managed entirely by Github. 
It has the following features:
  1. There are a total of 3 OS that can be used inside the "runs-on":
     - ubuntu-latest
     - windows-latest
     - macos-latest
  2. Each job runs on a seperate and isolated runner. No other job can have access to the files or the code of the other jobs within the workflow.
```

Write in your notes: Why does it matter that runners come with tools pre-installed?
```bash
This is so bcz:
1. The yml file remains clean and readable bcz we don't have to write the complex code as the pre-build tools are alreday available.
2. Every time we want to run some application like nginx, python etc, we don't have to build their images from the very scratch and we can simply use the pre-build tools that are available to save the build time of the heavy engine.
```

2. Set `runs-on: self-hosted`

1. Add a **label** to your self-hosted runner (e.g., `my-linux-runner`)
2. Update your workflow to use `runs-on: [self-hosted, my-linux-runner]`
3. Trigger it — does it still pick up the job?

Write in your notes: Why are labels useful when you have multiple self-hosted runners?
```bash
when there are multiple self-hosted runners than it is adviced to use the labels so that github knows which local machine is running which task!
Without labels, github won't know which local machine should execute which task.
```

### Task 6: GitHub-Hosted vs Self-Hosted
Fill this in your notes:

| | GitHub-Hosted | Self-Hosted |
|---|---|---|
| Who manages it? | Github | Me(My local) |
| Cost | free(upto monthly minutes) | free(unlimited) |
| Pre-installed tools | YES(maintained by gitub) | NO(Only those installed by you on your local) |
| Good for | Standard CI/CD pipelines, Open-source etc | heavy compilation work like gpu etc |
| Security concern | NO(Every task uses a completely fresh virtual machine) | YES(Every task runs on local machine) |

## Hints
- Runner setup script is generated by GitHub — just copy and run it
- Self-hosted runner runs as a background service: `./run.sh`
- To run as a service (persistent): `sudo ./svc.sh install && sudo ./svc.sh start`
- `runs-on: self-hosted` targets any self-hosted runner
- `runs-on: [self-hosted, linux, my-label]` targets specific ones
